How the transit map is drawn

The Lab's home page shows every dashboard as a station on a coloured line. Nobody draws it by hand: a few rules turn a plain list of pages into the map each time the page loads. Poke the rules here.

Key idea: the map is data plus rules. Change the data (a new page, a new link) and the same rules draw a new map, so the picture can never fall out of date.

1. Data in: one entry per page

Every dashboard already has an entry in the Lab's page list for the menu. The map reads four of its fields.

Analogy: a real transit authority keeps a timetable, and the map printer turns it into a diagram. Here the page list is the timetable and the home page is the printer, reprinting every time someone opens it.
{
  title:   'GitLab Pages and CI',
  href:    'devops/gitlab/gitlab-pages-ci.html',
  section: 'DevOps',    // which line
  topic:   'gitlab',    // small label under the station
  added:   '2026-10-31', // order along the line, and "NEW"
  related: ['security/csp-explained.html']  // interchange
}

Field by field

  • section, or topic when there's no section, picks the line. DevOps is one line holding both Git and GitLab pages.
  • added orders stations along a line, oldest first, like a journey from basics onward. Pages from the last 14 days show NEW.
  • related is optional. Each link to a page on another line becomes an interchange: a ringed station joined by a dotted transfer.
  • Separate sites, like Hangul Study, come from a short list of outside links and hang off the end of their topic's line as a dashed spur.

3. Ordering the lines

A transfer between two lines that aren't neighbours has to cross the lines in between. The home page orders lines to keep transfers short. Compare it with plain alphabetical order.

Analogy: seating guests at a long table. Put people who talk to each other side by side, and nobody has to shout across three others.

How "connected lines together" works
  1. Count the links between every pair of lines.
  2. Start with the line that has the most links in total.
  3. Next, take the line with the most links to the one just placed. If none link to it, take the one with the most links to any placed line, then the biggest line.
  4. Repeat until every line is placed.

This is a simple "greedy" rule: it makes the best next choice without planning ahead. It isn't guaranteed to find the very best order, but with a handful of lines it's quick and usually right.

4. When it doesn't fit

Each station needs room for its name. When the longest line can't fit across the screen, the home page switches to route cards instead of making you scroll sideways. Drag the width.


    

  






  
5. Readable for everyone

  
A map that only works with a mouse, or only for good eyesight, leaves people out. Three small choices make it work more widely.

  

    
Stations are real links
Each station is a link you can reach with the Tab key, with a name like "CSP, Explained, Security line, interchange" for screen readers. Focusing a station shows the same details as hovering.

    
Not colour alone
Every line carries its name on a label, interchanges have a thicker ring, and separate sites are squares on a dashed spur. Colour helps, but you never need it to tell things apart.

    
A halo behind text
Transfers sometimes pass under station names. Each name is drawn with an outline in the background colour first, so the dots stop short of the letters. Try it:
