Cloudflare and R2, Explained

How Cloudflare works, what R2 storage is, how to start, and how it fits with your GitLab Pages site

Cloudflare is a giant network that sits in front of your site

Cloudflare runs data centers in hundreds of cities. When a domain uses Cloudflare, visitors reach the nearest Cloudflare edge, not your server. The edge answers from its cache when it can, filters attacks, and goes to your server (the origin) only when it has to.

R2 = object storage with no egress fees

Object storage
It stores whole files ("objects") in containers called buckets. You put, get, list and delete whole files. You don't edit part of a file or mount it like a drive.
S3-compatible
It speaks the same API as Amazon S3, so the AWS SDKs, AWS CLI and rclone work by changing the endpoint and setting region: auto.
Zero egress
Reading data out of R2 is free. You pay for stored GB and for the number of operations, not for bandwidth.
Analogy: a bucket is a warehouse, and each object is a sealed box with a label (its key). The warehouse has no real shelves or rooms. A label like videos/intro.mp4 only looks like a folder path. Most warehouses charge a fee every time a truck drives a box out (egress). R2 charges only for floor space and for each time a worker handles a box.

Using them together

Keep small HTML in Git, served by GitLab Pages. Put large or binary files in R2, served from a custom domain. The browser loads the page from one and the files from the other.

Analogy: GitLab Pages is the menu board at the counter, which is light and changes often. R2 is a big warehouse next door that holds the bulky goods. The menu says "pick up item 7 at the warehouse window," and the customer's browser collects both.

CSP and CORS: why your page might block R2

    
Your dashboards use a strict Content Security Policy and are fully offline today. Loading anything from R2 means the page needs the network, and the CSP has to allow that domain. Toggle the settings and test.

Before you use this at work

    

      Public means the whole internet. GitLab Pages access control protects your pages, not files in a public R2 bucket. Anyone with an R2 URL can open that file. Never put security plans, internal data or anything sensitive in a public bucket.
    

    
    
      
  • Check with your security team before sending work data to a third-party cloud, and confirm Cloudflare R2 is approved for that kind of data.
    • 
      
  • Your self-hosted runner needs outbound access to <ACCOUNT_ID>.r2.cloudflarestorage.com. Corporate firewalls often block it.
    • 
      
  • Limit the API token to Object Read & Write on one bucket, store it as a masked, protected CI variable, and rotate it if it leaks.
    • 
      
  • For files the team should see only temporarily, use presigned URLs (up to 7 days) instead of making the bucket public.
