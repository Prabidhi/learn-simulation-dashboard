Why you saw the old page

You deploy a new version, reload, and the old one is still there. This page shows what the browser keeps, who it asks, what a fresh copy costs, and the one-line change that fixed it in the Lab.

Key idea: a browser files each saved page under its exact address and trusts it for a set time. Change the address even slightly and the browser has no saved copy, so it must ask the server.

1. The story, minute by minute

One dashboard, one deploy, one confused reader. Step through what the browser did and why.

Analogy: the browser keeps a photocopy of each page in a drawer, labelled with the page's address. A note on the copy says "good for 10 minutes". Until the note runs out, the browser reads the photocopy and never phones the library.

2. Who gets asked

Three parties are involved when you reopen a dashboard. Pick a case and see which of them hears from your browser, and how much comes back.

Cloudflare only answers "where is the site?". On the Lab site the pages themselves never pass through it, so its work is the same in all three cases. Browsers usually remember that answer too.

4. The fix: a tag on the address

The Lab's home page now adds a short tag to the address each time it opens a dashboard. The tag changes on every Lab visit. Try it with the tag on and off.

Analogy: the drawer is searched by the exact label. Ask for "page.html?v=2" and the photocopy labelled "page.html?v=1" doesn't count, so the browser phones the library. The library ignores the tag and hands over today's page.
