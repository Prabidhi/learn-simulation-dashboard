ORDS, Tomcat and APEX Lab

One practice lab, built in three stages: ORDS running by itself, the same ORDS inside Tomcat, then Oracle APEX added on top. This page shows where each piece runs, which database account answers each web address, and what every error along the way turned out to mean.

Key idea: ORDS is two things. One half is a Java web app that turns web requests into database calls. The other half is a schema inside the database, ORDS_METADATA, that stores REST modules and OAuth clients. APEX pages need only the first half. REST and OAuth need both. Most of the surprises on this page come from that split.

Why an earlier Tomcat-in-a-container attempt failed

    
ORDS keeps its database password in a wallet file inside its config folder. That wallet was created on the laptop and could only be opened there. Copied into a Linux container, ORDS couldn't read the password, so it had no database connection and every request said it "could not be mapped to any database". Running Tomcat on the laptop itself, next to the wallet, avoided the problem. A Tomcat 10 container failed for a different reason: this ORDS build runs on Tomcat 9.
