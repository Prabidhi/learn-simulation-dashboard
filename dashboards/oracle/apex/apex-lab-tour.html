APEX Lab Tour

A first low-code app in a home Oracle lab, followed click by click from the browser down to the rows it changes.

Key idea: the app lives in one database schema as page definitions, your data lives in another, and every click is a trip between them.
This page simulates the lab. The values start from a real practice lab built on 12 November 2026, but nothing here connects to a database.

1. The map

Seven parts, in three places. Click a box to see what it holds. The dashed outline is the APEX schema: it holds both the engine and the app.

Analogy: APEX is a restaurant kitchen. The engine is the cook. App 100 is the cook's recipe binder, kept in the kitchen (APEX_240100). The ingredients (your rows) are in your pantry, LAB_DATA. Every order: the cook opens the binder at the right recipe, then takes ingredients from the pantry.

2. Inside APEX

Zoom into the database. Which accounts ORDS signs in with, where workspaces, users and apps are stored, and what changes when you add more. Click any box, follow a request, or add an app or a workspace.

Analogy: APEX_240100 is an office building with one front desk (the engine). Each workspace is a rented floor with its own staff list and binders (apps). Each floor gets keys to certain storerooms (schemas). ORDS_PUBLIC_USER is the courier allowed into the lobby; APEX_PUBLIC_USER is the visitor badge that only opens the front desk.

      4. What was built, in order

      One afternoon of work, from an empty workspace to nine pages.

      1. Workspace
        Signed in as the developer user

        Checked the database container and Tomcat were running, then did APEX's forced first-login password change.

      2. LAB_DATA
        Installed the EMP / DEPT sample tables

        SQL Workshop → Utilities → Sample Datasets created EMP (14 people), DEPT (4 departments) and a view joining them.

      3. Pages 1–3
        Created app 100, Employees

        An interactive report on EMP with a slide-in form. The wizard's "Include Form" tick didn't take the first time, so the report page was rebuilt with Page Designer's Create Page wizard.

      4. Pages 4–5
        A settings table

        APP_SETTINGS holds one row per setting. A trigger stamps the update time, and Is Active became an on/off switch.

      5. Pages 6–7
        Confirmation numbers

        A function builds numbers like 26-DOM-0005 from settings rows, moves a per-application counter on, and records each number in CONFIRMATIONS.

      6. Terms check
        BLS instead of FRED

        FRED's terms forbid storing its data in your own database. The same figures come from the Bureau of Labor Statistics, whose material is public domain.

      7. Page 9
        Economic Data chart

        A Python script fetches three series in one request and merges 352 monthly values into ECON_DATA. The chart reads only that table.

      8. Page 10
        BLS Live, a REST Data Source

        A network rule lets the APEX schema reach api.bls.gov on port 443 and nowhere else. APEX fetches the unemployment rate itself, caches it for a day, and a post-processing query turns the nested reply into Month, rate and note.

      9. Page 12
        Preferences drop-down

        Pick a department and press Save: a process updates the DEFAULT_DEPTNO row. The Employee form uses that row as the default for new employees.

      5. Two ways to show outside data

      Both pages show BLS numbers. They get them in opposite ways.

      Copy it in: Economic Data (page 9)

      Who fetches
      A script on the Mac, when you run it
      Where it lives
      Your own table, ECON_DATA
      History
      10 years, 3 series
      Freshness
      As old as the last run
      Setup
      No database network permission needed
      Allowed for FRED?
      No: FRED forbids storing. Fine for BLS.

      Ask each time: BLS Live (page 10)

      Who fetches
      APEX itself, as the page opens
      Where it lives
      APEX's cache, for one day
      History
      3 years, 1 series
      Freshness
      Same day
      Setup
      A network rule added as SYS, one host and port
      Watch out
      Without the cache, every view uses one of 25 free daily requests

      6. Quiz

      Sources (checked 12 November 2026)
      • BLS copyright information: BLS material is public domain; credit BLS as the source.
      • BLS API terms of service: cite the retrieval date and state that BLS cannot vouch for data after retrieval.
      • BLS API FAQ: version 1 needs no key and allows 25 queries a day.
      • FRED legal terms: no storing, caching or archiving FRED content.
